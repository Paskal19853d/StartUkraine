# ТЗ ДЛЯ CLAUDE CODE

## Модуль «Подарки загиблому» для `card?slug=`

### 1. ЗАДАЧА

Расширить существующую страницу мемориала `card?slug=` новым функционалом **«Подарки загиблому»**.

Изначально возле свечи нет никаких подарков — только существующая анимация горящей свечи.

Авторизованный пользователь может выбрать подарок из каталога, оплатить его через **ПриватБанк**, после подтверждения оплаты подарок появляется возле свечи.

Первое появление подарка:

**GIF с руками → возложение подарка → GIF заканчивается → GIF заменяется статичным изображением подарка.**

При следующих посещениях страницы подарок сразу отображается на своем постоянном месте без повторной анимации.

---

### 3. ПОЛЬЗОВАТЕЛЬСКИЙ СЦЕНАРИЙ

1. Пользователь открывает `card?slug=`.
2. Видит свечу и пустое пространство вокруг нее.
3. Нажимает **«Подарки загиблому»**.
4. Если пользователь не авторизован — используется существующая Google-авторизация.
5. Пользователь видит каталог доступных подарков.
6. Выбирает подарок.
7. Видит название, описание и цену.
8. Подтверждает покупку.
9. Оплачивает через ПриватБанк.
10. После подтверждения успешной оплаты подарок привязывается к конкретному мемориалу.
11. При первом отображении запускается GIF возложения.
12. После завершения GIF остается статичное изображение подарка.
13. При последующих посещениях показывается сразу статичный подарок.

---

### 4. КАТАЛОГ ПОДАРКОВ

Подарки не должны быть жестко прописаны в коде.

Каждый подарок должен иметь возможность содержать:

* название;
* короткое описание;
* цену;
* категорию;
* основное изображение;
* GIF возложения;
* финальное изображение;
* активность;
* порядок отображения;
* параметры размещения.

Примеры:

* цветы;
* букеты;
* мягкие игрушки;
* конфеты;
* фрукты;
* свечи;
* памятные композиции;
* другие предметы.

Новые подарки должны добавляться из админ-панели без изменения кода.

---

### 5. НЕСКОЛЬКО ПОДАРКОВ

Один мемориал может иметь несколько приобретенных подарков.

Каждый подарок должен иметь собственное место размещения и корректно отображаться вместе с другими.

Не допускать неконтролируемого наложения предметов.

Должны учитываться:

* позиция;
* размер;
* порядок отображения;
* область размещения;
* необходимые визуальные параметры.

---

### 6. ОПЛАТА

Использовать **ПриватБанк**.

Подарок считается приобретенным только после подтверждения успешной оплаты.

Предусмотреть состояния:

* создан;
* ожидает оплаты;
* успешно оплачен;
* отменен;
* ошибка;
* неизвестный статус.

Цена и статус оплаты обязательно проверяются на серверной стороне.

Защитить систему от:

* изменения цены пользователем;
* подмены мемориала;
* подмены пользователя;
* фиктивного успешного платежа;
* повторного зачисления одной оплаты;
* изменения чужой покупки.

---

### 7. ХРАНЕНИЕ ПОКУПКИ

Каждая подтвержденная покупка должна быть связана с:

* конкретным мемориалом;
* конкретным пользователем;
* конкретным подарком;
* платежом;
* стоимостью;
* датой;
* статусом;
* состоянием отображения/анимации.

Если подарок перестал продаваться или был отключен в каталоге, ранее приобретенные подарки не должны исчезать с мемориалов.

---

### 8. АНИМАЦИЯ

Для каждого подарка предусмотреть возможность указать:

* GIF возложения;
* финальное статичное изображение;
* длительность/параметры анимации при необходимости.

Логика:

```text
новый оплаченный подарок
        ↓
GIF с руками
        ↓
возложение
        ↓
окончание GIF
        ↓
статичное изображение
        ↓
постоянное отображение
```

Анимация не должна запускаться повторно при каждом открытии страницы.
