# 1. ГЛАВНАЯ ЦЕЛЬ ЗАДАЧИ

Необходимо расширить существующую систему сайта «Зоряна Пам'ять».

Сейчас пользователи могут бесплатно добавлять на сайт погибших в войне с Россией, преимущественно военнослужащих.

Необходимо превратить систему из:

> **«Карточка погибшего военнослужащего»**

в:

> **«Универсальная страница памяти человека»**

Система должна позволять создавать страницы памяти для:

1. Военнослужащих, погибших в войне.
2. Гражданских, погибших вследствие войны.
3. Гражданских, погибших от ракетных ударов, Shahed/БПЛА, обстрелов и других военных воздействий.
4. Людей, умерших от болезни.
5. Людей, умерших от старости.
6. Людей, умерших вследствие несчастного случая.
7. Людей, умерших по другим причинам.
8. Других категорий в будущем.

При этом существующие военные карточки, данные и БД должны продолжить работать без потери информации.

# 5. ДАННЫЕ НЕ ДУБЛИРОВАТЬ ИЗ-ЗА ЯЗЫКА

Один человек должен существовать в БД как одна сущность.

Переключение:

`UA ↔ EN`

не должно создавать второго человека.

Например:

```text
person_id = 125
```

остается одним и тем же.

Язык меняет отображение, а не саму сущность.

```text
IF user has permission to manage people:

ELSE IF add_mode == FREE:
    allow create

ELSE:
    deny create
```

Проверить:

* обычный POST;
* AJAX;
* REST API;
* прямой API-запрос;
* мобильную версию;
* старые endpoints;
* альтернативные формы.

При платном режиме обычный пользователь не должен иметь возможности обойти ограничение.

Главное:

### 1.

**Не потерять существующие данные.**

### 2.

**Не сломать существующую БД.**

### 3.

**Не сломать существующие военные карточки.**

### 4.

**Сделать карточку и страницу-памятник универсальными для всех людей.**

### 5.

**Военные поля показывать только военным.**

### 6.

**Гражданские должны иметь полноценную страницу памяти, а не урезанную военную карточку.**

### 7.

**Люди, умершие от болезни, старости или других причин, также должны иметь полноценную страницу памяти.**

### 8.

**Вся система должна полноценно работать на украинском и английском языках через существующий Polylang.**

### 9.

**При платном режиме самостоятельное добавление не должно исчезать — оно должно переходить в формат заявки через колл-центр.**

### 10.

**Сервер должен реально блокировать самостоятельное создание записей при платном режиме.**

### 11.

**Все существующие данные и связи БД должны быть сохранены.**

### 12.

**Архитектура должна быть подготовлена к будущему добавлению онлайн-оплаты, но сама оплата сейчас не реализуется.**
